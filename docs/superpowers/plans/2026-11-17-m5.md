# M5 Live Class implementation plan

**Spec:** ../../../AGENTS.md M5. User requested continuation. Keep existing feature checkout/local preview, independent Nuxt4/Express5 apps, TS strict, mysql2 prepared SQL, Thai UI, Anuphan/palette. M5 only; no scheduler/admin extensions.

## Architecture and contract

Use existing live_sessions/live_tokens/live_attendance tables, no schema migration. API is the attendance authority. Jitsi IFrame is configured by server JITSI_DOMAIN. Only successful authenticated token entry exposes room_name; list/attendance never do. Live join tokens random32bytes hex, two-hour expiry, scoped to session+current account; reusable until expiry to allow re-entry, unlike Telegram one-use linking tokens. used_at records first entry. First joined_at retained across re-entry; left_at is latest observed exit (one row/user/session).

GET join keeps AGENTS route and requires X-Live-Join:1 header in addition to cookie+token; rejects cross-site Sec-Fetch-Site. This prevents navigation/prefetch and cross-site cookie GETs from recording attendance. Frontend calls it only on an explicit entry action, not SSR. Telegram links go to /live/join?t=token; session login redirect preserves only this safe local path. Remove token from browser URL before loading Jitsi, use Referrer-Policy:no-referrer. Reload may require obtaining a new link from classroom. No token in logs/notification_log payloads.

API envelopes {data:...} and existing {error:{code,message}}:
- GET /api/classes/:id/live => {sessions:LiveSession[]} current owner/member, archives readable.
- POST /api/classes/:id/live/start {title:string} =>201 {session}; owning teacher only, active class, one active session/class.
- POST /api/live/:id/link {} =>201 {url:string,expires_at:string}; owner/member, live active, active class; URL /live/join?t=64hex for current account.
- GET /api/live/join?t=64hex plus X-Live-Join:1 => {session,room_name,display_name,domain}; current account token and class access, records attendance. No room before validation.
- POST /api/live/:id/leave {} =>204; current owner/member, idempotent; cookie CSRF Origin applies to fetch/sendBeacon. Allowed after end/archive for cleanup.
- POST /api/live/:id/end {} =>{session}; owner only; closes all open attendance and blocks joins, idempotent, allowed on archived class for cleanup.
- GET /api/live/:id/attendance =>{session,students: [{user_id,name,joined_at,left_at}]}; owner only, current active student members, missing rows joined_at=null. Teacher excluded. Timestamps ISO UTC.
- POST /api/live/:id/remind-absent {} => ReminderResult as M4; owner, ended session only, absent current active students only; recheck absence/member/end after send queue wait. 1/minute/teacher. Non-Telegram students can enter from classroom independently.

LiveSession fields/interface exactly in backend/src/live.ts; frontend duplicates types, no cross imports. title trimmed1..200. IDs positiveuint32. Every request zod strict inputs/no query except join. New domain errors LIVE_NOT_FOUND404, LIVE_ALREADY_ACTIVE409, LIVE_ENDED409, INVALID_LIVE_TOKEN400, LIVE_NOT_ENDED409 plus existing auth/class errors. Role/auth and DB access every endpoint. Class-first transactions match archive/removal; serialize start/end/join and recheck expiry at lock acquisition.

## Constraints and limits

Jitsi public room URL is a separate access system: Student Tag scopes its own tokens/attendance, cannot prevent someone sharing the Jitsi room URL directly or enforce external moderator rights. No Jitsi JWT/self-hosted deployment added. Public meet.jit.si creator authentication may require separate tab; do not bypass login. End closes app session, cannot forcibly destroy public Jitsi rooms. Student names/audio/video go to configured Jitsi only after entry; explain on entry screen, recommend controlled self-hosting for production. No camera/mic permission or third-party login automation without user action. Live clock/check-in is best effort from client events; not identity/proctoring proof. No real Telegram credentials available at M4; recheck configuration booleans only, never print secrets.
