## Scheduled reminder decisions

Every minute via node-cron, only when Telegram configured; run once at startup, stop/wait on shutdown. 24h window: future due>3h and<=24h; 3h window: future due<=3h. No past-due/undated/archived/inactive/submitted targets. Catch-up windows avoid missed exact-minute triggers; if starting with2h left, send only3h reminder. Use M4 notify for mute/link/failure/throttling and recheck due+current membership/missing after waiting in queue.

Use existing notification_log, no schema change. Dedicated MariaDB GET_LOCK scoped to database serializes job instances; retain connection while job runs and release on all paths. Before send, claim once per(user,assignment,window) by inserting skipped/DUE_RESERVED log row only if no earlier log of kind due_24h/due_3h exists. Claim is durable before network send. Shared notify accepts optional log writer callback to update that exact reservation row with actual result. Any attempt including skipped/failed remains deduplicated, and due edits do not reset a window. This at-most-once attempt prioritizes no duplicates over recovery: a crash after reservation can lose a reminder; no automatic ambiguous send retries. In-process noOverlap plus cross-process advisory lock; release destroys broken/uncertain connection rather than returning a locked one to pool. Lock loss must prevent further sends.
