# M2 Implementation Plan

**Goal:** Teachers create/edit/archive classrooms, students join by code, teachers remove members and publish announcements visible only to their classroom.
**Spec:** ../../../AGENTS.md, milestone M2. Continue the existing independent Nuxt/Express apps and user-selected palette.
**Approach:** Reuse auth, errors, mysql2 pool, API fetch and visual styles. Add a classroom repository and router; independently maintain frontend types from docs/api.md. No new dependencies or schema changes are required.

## Decisions

- Only the owning teacher and enrolled students can read a classroom, its stream and people. Admin does not bypass classroom permissions.
- Join codes are random uppercase hexadecimal, 12 characters, unique DB constraint with bounded collision retries. Codes are exposed only to the owning teacher. Existing seed SCI2026 remains supported.
- Joining is idempotent. Rate limit join attempts to 20/minute per client IP.
- Archive is read-only: preserve access to existing data; reject join, edit, post and member removal. No restore feature in M2.
- Students can see member names and IDs, but not email addresses or join codes. All state-changing SQL additionally checks active classroom status to cover archive races.
- Stream is newest first; work and teacher-only grades tabs explicitly describe M3 availability without implementing assignments/grading early.
