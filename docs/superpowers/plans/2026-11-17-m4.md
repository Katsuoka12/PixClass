# M4 Telegram implementation plan

**Goal:** Complete AGENTS.md M4 only: private account linking, Telegram notifications, teacher reminders and bot commands.
**Spec:** ../../../AGENTS.md. User requested execution of this milestone; routine implementation decisions follow section 10.6.
**Architecture:** Existing Express/Nuxt apps stay independent. Add a SQL TelegramStore, grammy adapter and notification service injected into routes. Writes commit before notifications; failed delivery never undoes classroom work. No schema change, queue or cron in M4. Polling in dev; secret-authenticated webhook in production. Work continues in the existing feature checkout to preserve the local demo environment.

Expose only connected/muted status to web. Bot queries use current membership/ownership. Snapshot recipients for active classes/missing submissions; recheck at send time.

Per-teacher reminder rate 1/minute; link rate 5/15min.
- [x] Nuxt UI: /profile with account, Telegram status/connect/refresh; header link; teacher missing reminder button and counts. Keep Anuphan and palette, Thai UI, keyboard access, responsive layout. Own frontend types match contract above. Reminder request timeout 120s.
- [x] Final: both typechecks/builds, full API/DB suite, mock Telegram update-to-notification flow and UI check, independent review, docs/api.md and READMEs including BotFather/tunnel/webhook secrets and limits, then feat(m4) milestone commit.

## Decisions and review focus

Store raw link tokens only in existing token table; never log them, invalidate previous token on creation. Linked accounts cannot move to a different chat in MVP; show clear error, preventing silent message redirection. Mute affects automatic notifications only, commands still reply. Missing reminders exclude any submission including ungraded/late. Sends run sequentially in each batch and through one process-wide limiter. No persistent retry queue: delivery failures logged, manual retry possible; process restart can lose an in-flight notification. Real Telegram test needs bot credentials and a private chat; never claim it passed using a stub. Test transport uses grammy API transformers with fabricated data only.
