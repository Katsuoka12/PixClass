## API contract for implementers

JSON success `{data:...}`; existing safe error envelope. ISO dates UTC; due_at input ISO with explicit timezone, nullable. IDs positive uint32.

- GET/POST `/api/classes/:id/assignments` -> `{assignments: Assignment[]}` / 201 `{assignment:Assignment}`. POST input AssignmentInput; description defaults empty, due_at null, max_points100, allow_late true. Title1..200, description0..5000, max_points integer1..9999.
- GET/PATCH/DELETE `/api/assignments/:id` -> `{assignment:Assignment}` / same /204. PATCH partial nonempty AssignmentInput. Teacher owner writes, owner/enrolled student reads.
- GET `/api/assignments/:id/submission` -> `{submission:PublicSubmission|null}` student own only.
- PUT same -> `{submission:PublicSubmission}` student. JSON `{answer_text:string,remove_file?:boolean}` or multipart `answer_text`, optional `file`, optional `remove_file` string true/false. Text max5000, text and/or file required; omitted file preserves existing. remove_file true removes old attachment, cannot combine with new file. Can't edit after graded or after deadline if allow_late=false. New submission returns200.
- GET `/api/assignments/:id/submissions` -> `{submissions:SubmissionRow[]}` owning teacher; rows include every current student, missing/submitted/late and nested PublicSubmission|null.
- PATCH `/api/submissions/:id/grade` -> `{submission:PublicSubmission}` owning teacher, `{grade:number,feedback?:string}` grade0..max_points, at most2decimal places, feedback0..5000 defaults empty. Regrading allowed, no ungrade operation.
- GET `/api/submissions/:id/file` -> attachment (authenticated fetch/open same origin); only submission owner or owning teacher with current class access.
- GET `/api/classes/:id/gradebook` -> Gradebook for teacher. Students have id,name,submissions array.
- GET `/api/me/todo` -> `{items:TodoRow[]}` student; enrolled active classes only. Status missing/submitted/late/graded.

Assignment, SubmissionRow, Gradebook, TodoRow fields defined in backend/src/assignments.ts. PublicSubmission omits file_path and adds file_url:string|null pointing at `/api/submissions/:id/file`; frontend defines its own matching types. No original-name file path exposed. Error codes: ASSIGNMENT_NOT_FOUND404, SUBMISSION_NOT_FOUND404, FILE_NOT_FOUND404, FORBIDDEN403, CLASS_ARCHIVED409, ALREADY_GRADED409, DEADLINE_PASSED409, GRADE_EXCEEDS_MAX400, MAX_POINTS_BELOW_GRADE409, EMPTY_SUBMISSION400, INVALID_FILE400, FILE_TOO_LARGE413, existing validation/auth/CSRF errors. Store uses ApiError for domain failures.

## Decisions

Keep M2 archive read-only behavior. Grade 0 is graded (must check graded_at/null, not truthiness). Late if submitted_at > due_at. Due dates edited by teacher recalculate late display. No withdrawal; existing attachment persists unless explicitly replaced/removed. Delete confirmation UI; cascade explicit inside transaction (existing FK doesn't cascade). No schema change needed. Store datetimes with UTC_TIMESTAMP and mysql2 timezone Z. Upload processing uses disk; real MIME signatures are checked, not browser Content-Type. Signature check is not malware scanning; documented limit. Files limited PDF/JPEG/PNG/DOCX, one per submission.
